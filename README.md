# Відеозаставка магазину (PWA)

Progressive Web App для планшетів і смартфонів у магазині: відео починає
грати одразу при запуску застосунку і крутиться в циклі без зупинки; дотик по
екрану не ховає відео, а виходить із застосунку (на Android — див. примітку
про iOS нижче). Є прихована адмін-панель для керування відео та
налаштуваннями. Без бекенду — увесь застосунок client-side, без
кроку збірки (просто статичні файли).

## Структура проекту

```
store-screensaver-pwa/
├── index.html              # HTML-каркас (основний екран, заставка, адмін-панель)
├── manifest.json           # PWA-маніфест (fullscreen/standalone, іконки)
├── service-worker.js       # Кешування "оболонки" застосунку для офлайн-роботи
├── css/
│   └── style.css           # Стилі (адаптивні, з підтримкою safe-area)
├── js/
│   ├── main.js              # Точка входу: зв'язує всі модулі
│   ├── db.js                 # IndexedDB: відео (local/synced) і налаштування
│   ├── screensaver.js        # Постійний показ/приховування та відтворення відео
│   ├── adminPanel.js         # Адмін-панель (потрійний тап, форма, save/exit, вибір джерела)
│   ├── videoSource.js         # Перемикає активне джерело відео: local / synced
│   ├── exitApp.js              # Вихід із застосунку при дотику по екрану
│   ├── sync.js                 # Firebase: завантаження/підписка/видалення синхр. відео
│   ├── firebase-config.js      # Ваші ключі Firebase (заповнити для синхронізації)
│   ├── install.js              # Пропозиція встановити PWA (beforeinstallprompt + iOS)
│   ├── wakeLock.js              # Screen Wake Lock (не давати екрану засинати)
│   └── fullscreen.js            # Визначення display-mode + Fullscreen API
├── icons/
│   ├── icon-192.png
│   ├── icon-512.png
│   └── icon-maskable-512.png
└── FIREBASE_SETUP.md       # Покроково: налаштування синхронізації відео
```

## Технології та рішення

- Чистий HTML/CSS/JavaScript (ES-модулі), **без бандлера і без кроку збірки**.
  Це свідомий вибір: PWA для кіоску має розгортатись копіюванням файлів на
  будь-який статичний HTTPS-хостинг, без `npm run build` щоразу.
- IndexedDB для відео (Blob напряму, без base64) і для налаштувань.
- Service Worker кешує лише "оболонку" застосунку (HTML/CSS/JS/іконки) —
  відео в кеш service worker не потрапляє, воно живе в IndexedDB.

## Запуск локально (для розробки й тестування)

PWA, Service Worker та деякі API не працюють при відкритті файлу напряму
(`file://`) — потрібен http(s)-сервер. Будь-який із варіантів:

```bash
# Python
python3 -m http.server 8080

# Node.js
npx serve .
```

Потім відкрити виведену адресу (наприклад, `http://localhost:8080`) у браузері.
`localhost` прирівнюється браузерами до HTTPS, тож усе працює й локально.

## Деплой на HTTPS

Встановлення PWA та Service Worker вимагають HTTPS (окрім `localhost`).
Найпростіші безкоштовні варіанти — завантажити всю структуру проекту (усі
файли й папки цілком, зберігаючи їх розташування) в корінь одного з хостингів:

- **Netlify** — перетягнути папку проекту на app.netlify.com/drop.
- **GitHub Pages** — запушити репозиторій, увімкнути Pages у налаштуваннях.
- **Firebase Hosting** — `firebase deploy` після `firebase init hosting`.
- Власний сервер (nginx/Apache) із сертифікатом (наприклад, Let's Encrypt).

## Встановлення на Android

1. Відкрити сайт у Chrome.
2. З'явиться банер застосунку "Встановити" (або меню Chrome (⋮) →
   "Встановити застосунок" / "Додати на головний екран").
3. Після встановлення застосунок відкривається окремою іконкою, без адресного
   рядка браузера.

## Встановлення на iPhone / iPad

1. Відкрити сайт **у Safari** (встановлення PWA на iOS підтримує лише Safari,
   не Chrome чи інші браузери).
2. Натиснути кнопку "Поділитися" (квадрат зі стрілкою вгору).
3. Обрати "На екран Домівка".
4. Підтвердити додавання.

iOS Safari не підтримує подію `beforeinstallprompt`, тому застосунок сам
визначає iOS і показує саме цю текстову інструкцію замість автоматичної кнопки.

## Як змінити відео

Після відкриття застосунку: тричі швидко натиснути (потрійний тап) у
правому верхньому куті екрана (невидима зона ~84×84px) → відкриється
адмін-панель → обрати джерело відео → "Обрати файл відео".

Два джерела на вибір (перемикач угорі секції "Відео"):

- **Локальне** — відео зберігається в IndexedDB тільки цього пристрою;
  кожен пристрій налаштовується окремо. Нічого додатково готувати не треба.
- **Синхронізоване** — одне відео одразу для всіх пристроїв: завантажили на
  одному, решта підхоплюють автоматично (реальний час, через Firebase).
  Потребує Firebase Storage (план Blaze з оплатою за використання) та
  налаштування — покроково в **FIREBASE_SETUP.md**. Без конфігурації чи
  доступного Storage застосунок показує помилку замість падіння.

Немає більше таймауту: щойно відео завантажене й показ увімкнено
("Показувати відео" в адмін-панелі) — воно грає завжди. Дотик по екрану
виходить із застосунку (див. нижче); винятки, де дотик застосунок НЕ
закриває: невидима зона в правому верхньому куті (потрійний тап → адмінка),
сама адмін-панель разом із затемненим тлом і банер "Встановити застосунок".

## Як змінити назву та іконку застосунку

**Назва:**

- `manifest.json` → поля `name` (повна назва) та `short_name` (назва під
  іконкою).
- `index.html` → `<title>` та `<meta name="apple-mobile-web-app-title">`.

**Іконка:**

- Замінити файли `icons/icon-192.png`, `icons/icon-512.png` та
  `icons/icon-maskable-512.png` власними зображеннями тих самих розмірів
  (PNG, квадратні; maskable-версія має заповнювати весь квадрат без
  прозорості, оскільки лаунчер Android може обрізати її по колу/фігурі).
- Після заміни іконок підвищіть версію кешу в `service-worker.js`
  (наприклад, `CACHE_NAME = 'screensaver-shell-v4'`), інакше вже
  встановлені пристрої якийсь час показуватимуть стару іконку зі свого
  кешу. Те саме стосується будь-якої зміни файлів проєкту — і особливо
  `js/firebase-config.js` після заповнення реальними ключами.

## Технічні примітки та обмеження браузерів

- **Тестуйте встановлений застосунок, а не вкладку браузера.** Смуги/панелі
  браузера (адресний рядок тощо) видно лише в звичайній вкладці — вони
  зникають тільки після встановлення PWA на головний екран. Якщо після
  встановлення ще лишається зайва смуга — це один з пунктів нижче.
- **Fullscreen на Android.** `display: "fullscreen"` підтримується
  переважною більшістю сучасних Chrome/Chromium-браузерів на Android (з
  2017 року) — після встановлення застосунок має ховати і статус-бар, і
  навігаційну панель повністю. Якщо конкретний пристрій усе ж не підтримує
  цей режим, застосунок автоматично переходить на наступний у списку
  `display_override` — `"standalone"` (без адресного рядка, але зі
  статус-баром зверху — це поведінка браузера, керувати нею з коду не можна).
- **Верхня панель (статус-бар) на iPhone/iPad неможливо прибрати повністю —
  це обмеження iOS, а не застосунку.** Safari підтримує лише `standalone`
  для PWA (`fullscreen` там не працює в принципі), і навіть у цьому режимі
  статус-бар (час/заряд/сигнал) завжди залишається на екрані — Apple не
  дає вебзастосункам ховати його. `apple-mobile-web-app-status-bar-style:
black-translucent` (уже увімкнено в коді) робить його прозорим і вміст
  малюється під ним, тому це максимум, чого можна досягти без переходу на
  нативний застосунок.
- **Чорна смуга знизу на iPhone/iPad.** Це відомий і задокументований баг
  WebKit (bugs.webkit.org #236445 та інші): у встановлених на головний
  екран PWA видима висота екрана іноді "застрягає" зменшеною (типово після
  повернення з фону чи довгого сеансу), і жодні CSS-одиниці (`100dvh`,
  `100%`, `safe-area-inset-*`) це не виправляють, бо сам браузер віддає їм
  неправильне значення. Обхід, який я додав: при поверненні застосунку на
  передній план (і додатково кожні 5 хв про всяк випадок) код примусово
  "струшує" верстку (`display: none` → назад, синхронно, непомітно для
  ока), що змушує WebKit перерахувати розмір наново — це задокументований
  спільнотою робочий обхід саме цього багу. Це не 100%-гарантія (сам баг —
  на боці Apple, я лише змушую його "перевіритись" частіше), тож перевірте,
  будь ласка, чи стало краще на вашому пристрої.
- **Гучність на iOS.** Safari на iPhone/iPad навмисно ігнорує програмне
  встановлення `video.volume` — це обмеження WebKit, а не помилка коду.
  Повзунок гучності в адмін-панелі повністю працює на Android і desktop,
  але на iPhone/iPad звук регулюється лише апаратними кнопками пристрою.
- **Screen Wake Lock — підтверджений баг саме у встановлених PWA на iOS.**
  Офіційний Screen Wake Lock API підтримується в Chrome/Edge на Android і
  в Safari з iOS 16.4+ **у звичайній вкладці браузера** — але в PWA,
  встановленому на головний екран, це API в iOS до версії 18.4 включно
  зламане (підтверджений баг WebKit #254545): метод відпрацьовує без
  помилки, а екран усе одно блокується. Тому застосунок тепер додатково
  запускає незалежну від цього багу техніку — приховане крихітне
  беззвучне відео, яке постійно "живе" (перемотується), що зазвичай
  переконує iOS не присипляти екран навіть там, де офіційний API мовчки
  не працює (техніка перевірена спільнотою, бібліотека NoSleep.js). Це теж
  best-effort, а не гарантія на 100% пристроїв — якщо у вас iOS 18.4+,
  спробуйте також офіційний API окремо (він мав би просто запрацювати).
- **Вихід із застосунку по дотику.** Реалізовано через `window.close()`
  (js/exitApp.js). У встановленому на головний екран PWA на Android це
  закриває застосунок і повертає на головний екран телефона (за звітами
  розробників; на реальному Android-пристрої я це перевірити не міг — дайте
  знати, якщо не спрацює). **На iPhone/iPad так вийти неможливо:** iOS не дає
  вебзастосункам жодного способу закритись самостійно, тож там дотик нічого
  не робить (відео продовжує грати) — вийти можна лише свайпом угору від
  нижнього краю екрана. Спрацьовує на завершений дотик (`click`), тому
  системні жести на кшталт свайпу від краю застосунок не закривають.
- **Fullscreen API (захист від випадкового виходу).** Використовується як
  додатковий рівень, коли сторінка відкрита в браузері (не встановлена як
  PWA). Потребує жесту користувача, тому активується на перший дотик і
  повторно — на наступний дотик після виявленого виходу з fullscreen.
- **Синхронізація відео між пристроями** — реалізована через Firebase
  (Storage + Firestore, реальний час через `onSnapshot`), перемикається в
  адмін-панелі. Налаштування — у **FIREBASE_SETUP.md**. Я перевірив, що
  застосунок коректно поводиться, коли Firebase не налаштовано (зрозуміла
  помилка, без падіння), але сам реальний обмін даними з Firebase не міг
  протестувати наскрізно — у мене немає мережевого доступу для створення
  тестового проєкту. Перевірте, будь ласка, на своєму проєкті і дайте знати,
  якщо щось піде не так.
