# Налаштування синхронізації відео (Firebase)

Потрібно лише для режиму **"Синхронізоване (усі пристрої)"** в адмін-панелі.
Якщо плануєте користуватись тільки локальним відео на кожному пристрої —
цей файл можна пропустити.

Як це працює: Firebase **Storage** зберігає сам відеофайл, **Firestore**
зберігає маленький документ-покажчик на нього. Усі пристрої в режимі
"Синхронізоване" підписані на цей документ у реальному часі — коли адмін на
одному пристрої завантажує нове відео, решта підхоплюють його автоматично,
без перезавантаження сторінки.

## 1. Створити проєкт

1. Відкрити [console.firebase.google.com](https://console.firebase.google.com).
2. "Add project" → ввести назву → можна вимкнути Google Analytics (не
   потрібен) → створити. Це безкоштовно (план Spark).

## 2. Увімкнути Firestore і Storage

У бічному меню проєкту:

1. **Build → Firestore Database → Create database** → режим "Start in
   production mode" (правила безпеки вставите нижче) → обрати регіон,
   найближчий до магазину.
2. **Build → Storage → Get started** → так само production mode → той самий
   регіон.

## 3. Зареєструвати веб-застосунок і отримати конфіг

1. На головній сторінці проєкту (значок шестерні → **Project settings**) →
   вкладка **General** → внизу "Your apps" → значок **</>** (Web).
2. Дати застосунку назву (будь-яку) → "Register app". **Firebase Hosting
   тут вмикати не потрібно** — файли й так деплояться окремо, за
   інструкцією в README.md.
3. З'явиться об'єкт `firebaseConfig` — скопіювати значення полів у файл
   `js/firebase-config.js` цього проекту (замінити плейсхолдери
   `ВАШ_...`).

## 4. Встановити правила безпеки

У цього застосунку немає системи логінів (адмін-панель захищена лише
потрійним тапом на пристрої), тому правила нижче дозволяють читання й запис
без автентифікації, але **обмежені конкретним шляхом** (не всією базою) і
базовою валідацією типу/розміру файлу. Будь-хто, хто дізнається ваш
`firebaseConfig` (він і так видимий у коді сторінки — це нормально для
Firebase-застосунків), теоретично зможе замінити відео. Для звичайного
магазинного кіоску це прийнятний компроміс; якщо потрібен суворіший захист —
розгляньте Firebase App Check.

**Firestore → вкладка Rules:**

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /screensaver/current {
      allow read: if true;
      allow write: if request.resource.data.keys().hasAll(['url', 'storagePath', 'fileName', 'updatedAt'])
                   && request.resource.data.url is string;
    }
  }
}
```

**Storage → вкладка Rules:**

```
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /videos/current.{ext} {
      allow read: if true;
      allow write: if request.resource.size < 500 * 1024 * 1024
                   && request.resource.contentType.matches('video/.*');
    }
  }
}
```

Натиснути "Publish" на обох вкладках.

## 5. Перевірити

1. Заповнити `js/firebase-config.js`, розгорнути файли на хостинг (як
   зазвичай — див. README.md), і **підняти версію `CACHE_NAME`** у
   `service-worker.js` (наприклад, на `v3`) — інакше пристрої, що вже
   встановили застосунок раніше, продовжать використовувати старий
   закешований `firebase-config.js` із плейсхолдерами.
2. На одному пристрої: адмін-панель → обрати "Синхронізоване" → завантажити
   відео.
3. На іншому пристрої (або в іншій вкладці): адмін-панель → обрати
   "Синхронізоване" — відео має підхопитися автоматично, без ручного
   завантаження на цьому пристрої.

## Обмеження безкоштовного плану (орієнтовно)

Spark-план: 5 ГБ у Storage, ~1 ГБ вихідного трафіку на день, Firestore —
~50 тис. читань/20 тис. записів на день. Для невеликої кількості пристроїв
у магазині й нечастої зміни відео цього більш ніж достатньо. Якщо пристроїв
багато (десятки+) і відео важке та змінюється часто — трафік Storage може
наблизитись до денного ліміту; тоді варто стискати відео компактніше або
перейти на платний план (Blaze) — там ті самі ліміти, але з оплатою за
перевищення, а не блокуванням.

## Що я НЕ зміг перевірити

Я написав і перевірив код у безмережевому середовищі — тобто підтвердив, що
застосунок коректно обробляє "Firebase не налаштовано" і не падає, але сам
реальний обмін даними з Firebase (завантаження, підписку в реальному часі)
перевірити не міг, бо для цього потрібен саме ваш, реально створений проєкт.
Якщо після налаштування щось піде не так — дайте знати, що саме, і я
розберусь далі.
